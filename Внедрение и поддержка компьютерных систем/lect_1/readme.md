## 💡 Определение

> **Компьютерные системы** — комплекс компьютерного, активного сетевого оборудования, системного и офисного программного обеспечения, необходимого для успешного функционирования комплексной автоматизированной системы предприятия.

---

## 📜 Нормативная база

**ГОСТ Р ИСО/МЭК 12207‑2010** «Информационная технология. Системная и программная инженерия. Процессы жизненного цикла программных средств»

- Идентичен международному стандарту **ИСО/МЭК 12207‑2008**
- Устанавливает общую структуру процессов жизненного цикла ПО
- Определяет процессы, виды деятельности и задачи при:
  - приобретении программного продукта или услуги
  - поставке, разработке, применении по назначению
  - сопровождении и прекращении применения программных продуктов
- Регламентирует процесс определения, управления и совершенствования процессов жизненного цикла ПО

> **Жизненный цикл ПО** — период разработки и эксплуатации программного обеспечения.

## 🚀 Подходы к запуску проектов внедрения ИС

### 1. Крупная компания-внедренец (аутсорсинг)
| ✅ Плюсы | ❌ Минусы |
|---------|---------|
| Опыт компании и специалистов | Высокая стоимость |
| Наличие проектных наработок | Возможная текучка кадров |
| | Риск несоответствия репутации реальному уровню |

### 2. Небольшая региональная IT-компания
| ✅ Плюсы | ❌ Минусы |
|---------|---------|
| Высокая вероятность приоритетности проекта | Риски при долгосрочных проектах |
| | Возможная смена руководства / специалистов |

### 3. Собственный IT-отдел
| ✅ Плюсы | ❌ Минусы |
|---------|---------|
| Нет дополнительных затрат | Зависимость от пользователей и руководства |
| Постоянная связь со специалистами | Ориентация на не всегда оптимальные решения |
| Возможность личного управления проектом | |

### 4. Приглашение эксперта
| ✅ Плюсы | ❌ Минусы |
|---------|---------|
| Экономия средств | Высокая организованность сотрудников обязательна |
| Привлечение узкого специалиста | Зависимость от одного человека |
| | Формальная ответственность за проект |

## 🔄 Основные этапы внедрения компьютерных систем

```
[1. Обследование] → [2. ТЗ] → [3. Настройка] → [4. Тестирование] → [5. Опытная эксплуатация] → [6. Промышленная эксплуатация]
```

| № | Этап | Содержание | Срок |
|---|------|------------|------|
| 1 | 🔍 **Обследование** | Диагностика всех процессов; определение цели внедрения | 1–4 нед. |
| 2 | 📝 **Разработка ТЗ** | Справочники, алгоритмы, отчётные формы, АРМ, права доступа | 1–3 мес. |
| 3 | ⚙️ **Настройка системы** | Формирование функционала, настройка рабочих мест и прав | 1–1,5 мес. |
| 4 | 🧪 **Тестирование** | Демо-пример, проведение теста, исправление ошибок | ~2 нед. |
| 5 | 🔬 **Опытная эксплуатация** | Работа с реальными данными параллельно со старой системой | ~1 мес. |
| 6 | 🏭 **Промышленная эксплуатация** | Полный переход, отказ от альтернатив, тех. поддержка | ~1 мес. |

## ⚠️ Типичные проблемы при внедрении

| # | Проблема | Причина / Следствие |
|---|----------|-------------------|
| 1 | **Недостаток прозрачности разработки** | Плохое планирование структуры, недостаточное финансирование |
| 2 | **Недостаток контроля** | Срыв графиков, превышение бюджета |
| 3 | **Недостаток мониторинга** | Невозможность наблюдать за ходом проекта в реальном времени |
| 4 | **Ненадёжность системы разработки ПО** | Сложность поиска ошибок, неопределённость сроков отладки |
| 5 | **Отсутствие гарантий на программы** | Сложность выбора надёжного поставщика ПО |
