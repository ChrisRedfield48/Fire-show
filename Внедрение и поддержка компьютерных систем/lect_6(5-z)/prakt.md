## 🛠️ 2. Результаты аппаратной диагностики (PC Wizard)

**PC Wizard** — это многофункциональный инструмент для глубокого анализа и тестирования компонентов ПК. Программа позволяет получить исчерпывающие сведения об оборудовании и провести синтетические нагрузочные тесты для оценки реальной производительности системы.



**Алгоритм выполнения диагностики:**
1. Запуск утилиты PC Wizard с правами администратора для получения полного доступа к датчикам.
2. Выбор необходимых сценариев тестирования для отдельных компонентов.
3. Проведение бенчмарков в штатном режиме (без оверклокинга/разгона).
4. Фиксация результатов в автоматическом режиме.
5. Экспорт отчёта для последующего анализа.

## 📚 4. Теоретическая база: Проблемы совместимости ПО

В рамках лабораторной работы были изучены теоретические аспекты совместимости программного и аппаратного обеспечения.

### ❓ 4.1. Ключевые причины возникновения конфликтов совместимости

Конфликты могут быть спровоцированы множеством факторов на разных уровнях архитектуры:

* **⚙️ Аппаратный уровень:**
  * Нехватка вычислительных ресурсов (недостаток ОЗУ, слабая видеокарта, медленный CPU).
  * Отсутствие в процессоре современных наборов инструкций (SSE4.2, AVX).
  * Специфические требования к накопителям (например, обязательное наличие NVMe SSD).
  * Отсутствие поддержки legacy-периферии (старые принтеры, LPT-сканеры).
* **💻 Программный уровень (ОС):**
  * Разница в поколениях ОС (софт для Windows 7 конфликтует с ядром Windows 11).
  * Архитектурные барьеры (попытка запуска 64-битного кода на 32-битной ОС).
  * Конфликт динамических библиотек (так называемый DLL-hell).
  * Изменения в системных вызовах и устаревшие драйверы.
* **🛡️ Уровень безопасности:**
  * Блокировка процессов системами UAC (Windows) или SELinux (Linux).
  * Срабатывание защиты целостности файлов (Windows Resource Protection) или агрессивных антивирусов.
* **👤 Человеческий и сетевой факторы:**
  * Ручное повреждение реестра, установка "пиратских" модификаций (модов, патчей).
  * Блокировка нужных сетевых портов или отсутствие постоянного интернет-канала для облачного ПО.

### 💡 4.2. Методология устранения проблем с совместимостью

Для предотвращения и лечения программных конфликтов применяется комплексный подход:

**Профилактика:**
* Сверка системных требований до начала инсталляции ПО.
* Своевременное обновление ОС и создание точек восстановления среды.

**Практические решения:**
1. **Режимы совместимости ОС:** Принудительный запуск проблемного ПО с эмуляцией среды старых ОС (например, Windows XP) и отключением современных визуальных эффектов.
2. **Обновление сред выполнения (Runtimes):** Установка свежих пакетов .NET Framework, Visual C++ Redistributable, DirectX и Java (JRE).
3. **Изоляция и виртуализация:** Развертывание приложения внутри виртуальной машины (VMware, VirtualBox), Docker-контейнера или "песочницы" (Sandboxie).

4. **Трансляторы и эмуляторы:** Использование слоев совместимости, таких как Wine (для Linux) или эмуляторов архитектуры вроде DOSBox/QEMU.
5. **Манипуляции с правами:** Запуск от имени Администратора, временная приостановка работы UAC или корректировка локальных политик безопасности.
6. **Обслуживание системы:** Регулярная проверка системных файлов утилитой `sfc /scannow`, мониторинг здоровья дисков (S.M.A.R.T.) и обновление микрокода BIOS/UEFI.
