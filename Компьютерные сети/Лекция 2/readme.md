## ⏳ 1. Историческая ретроспектива развития сетей



Развитие вычислительных сетей прошло путь от локальных экспериментов до создания глобальной информационной инфраструктуры. 

**Хронология ключевых событий:**

| Год / Период | Событие и его значение |
| :--- | :--- |
| **Начало 1970‑х** | Появление первых нестандартных локальных сетей, заложивших базу для объединения ЭВМ. |
| **1971 год** | Инженер Рей Томлинсон (компания BNN) написал первую в истории программу для работы с электронной почтой. |
| **1973 год** | Роберт Меткалф (исследовательский центр Xerox) предложил концептуальную идею и название технологии **Ethernet**. |
| **1974 год** | Выдающиеся инженеры Винтон Серф и Роберт Кан разработали фундаментальный протокол управления передачей **TCP**. |
| **1978–1979 гг.** | Разработка международной эталонной модели **OSI**, стандартизирующей сетевое взаимодействие. |
| **Начало 1980‑х** | Создание универсального стека протоколов **TCP/IP**, обеспечившего независимость компьютера от физической сети. Развёртывание TCP/IP на всех узлах ARPANET и фактическое формирование сети Интернет в её современном виде. |
| **Середина 1980‑х** | Разработка и внедрение стандартных технологий для локальных сетей: **Ethernet** (1980 г.), **Token Ring** (1985 г.) и оптической **FDDI** (1985 г.). |
| **2 ноября 1988 г.** | Первая масштабная кибератака: «червь Морриса» поразил около 6 000 узлов ARPANET, практически выведя сеть из строя. Как результат инцидента, была создана организация **CERT** (Computer Emergency Response Team) для реагирования на компьютерные инциденты. |
| **Рубеж 1980–1990‑х** | Постепенная замена устаревшей ARPANET на более современную **NSFNet** (сеть Национального научного фонда NSF США). |
| **1991–1992 гг.** | Тим Бернерс‑Ли и его коллеги (научный центр CERN) изобрели революционную технологию **World Wide Web (WWW)**. |
| **1994 год** | Создание протокола двухточечного соединения **PPP**. |
| **1995 год** | Замена научной сети NSFNet на коммерческую опорную сеть. Массовое появление коммерческих провайдеров — **ISP** (Internet Service Providers). Окончательный переход к современному статусу глобальной сети Интернет. |

## 🏗️ 2. Теория сетевого взаимодействия: Модели и Протоколы

Для обеспечения совместимости оборудования от разных производителей используются стандартизированные модели взаимодействия.

**Фундаментальные определения:**
* **Коммуникационный протокол:** строго формализованный набор правил взаимодействия узлов сети.
* **Стек протоколов:** иерархически организованный (многоуровневый) набор протоколов, применяемый для взаимодействия узлов в сети.

### 2.1. Эталонная модель OSI (Open System Interconnection)



[Image of OSI model 7 layers]


Данная модель была разработана в начале 80‑х годов международной организацией по стандартизации (ISO) как международный стандарт архитектуры компьютерной сети. Она жестко определяет уровни взаимодействия в сетях с коммутацией пакетов.

**Архитектура из 7 уровней (рассматривается снизу вверх):**

1. 🔌 **Физический уровень (Physical Layer):**
   * **Основная функция:** передача неструктурированного потока битов по физическим каналам связи (например, по медному кабелю "витая пара").
   * **Особенность:** реализуется аппаратно на всех без исключения устройствах, подключённых к сети.
   * **Пример реализации:** спецификация 100Base‑T4 стандарта Ethernet.

2. 🔗 **Канальный уровень (Data Link Layer):**
   * **Особенность:** это первый уровень, на котором появляется коммутация пакетов. 
   * **Единица данных (PDU):** кадр (frame).
   * **Функции:** доставка кадра между локальными узлами сети (LAN) или соседними узлами глобальной сети (WAN, протоколы PPP, HDLC).
   * **Ключевые задачи:** обнаружение и коррекция ошибок передачи, проверка доступности среды передачи данных (подуровень MAC).
   * **Оборудование:** реализуется сетевыми адаптерами, мостами, коммутаторами (свитчами) и маршрутизаторами.

3. 🌐 **Сетевой уровень (Network Layer):**
   * **Основная функция:** служит для межсетевого взаимодействия (internetworking) и физического объединения различных сетей.
   * **Единица данных (PDU):** пакет.
   * **Ключевая задача:** маршрутизация (определение оптимального маршрута доставки).
   * **Примеры протоколов:** IP, IPX, а также протоколы маршрутизации RIP, BGP.

4. 🚚 **Транспортный уровень (Transport Layer):**
   * **Основная функция:** обеспечивает передачу данных между конечными узлами с необходимой степенью надёжности. 
   * **Спецификация:** модель OSI определяет 5 классов транспортного сервиса (классы от 0 до 4).
   * **Единица данных (PDU):** сегмент (для TCP) или дейтаграмма (для UDP).
   * **Задачи:** реализация надежного транспортного соединения, мультиплексирование и демультиплексирование данных, управление потоком передачи.
   * **Примеры протоколов:** TCP, UDP.

5. 🤝 **Сеансовый уровень (Session Layer):**
   * **Основная функция:** управляет логическим взаимодействием сторон, устанавливает, поддерживает и синхронизирует сеанс связи.
   * **Пример протокола:** SSH.

6. 🎭 **Уровень представления данных (Presentation Layer):**
   * **Основная функция:** представляет информацию для прикладного уровня без изменения её смыслового содержания.
   * **Ключевые задачи:** унифицированное отображение данных, криптографическая защита (шифрование/дешифрование, например SSL), компрессия (сжатие) данных.

7. 💻 **Прикладной уровень (Application Layer):**
   * **Основная функция:** обеспечивает пользовательским приложениям доступ к разделяемым сетевым ресурсам и организацию совместной работы.
   * **Единица данных (PDU):** сообщение (message).
   * **Примеры протоколов:** FTP, SMB, NCP.

### 2.2. Модель Министерства обороны США (DoD / TCP/IP)



[Image of TCP/IP vs OSI model comparison]


Это более прагматичная четырёхуровневая модель сетевого взаимодействия, разработанная Министерством обороны США (Department of Defense). Её практической реализацией стал повсеместно используемый стек протоколов TCP/IP.

**Сравнение уровней DoD и OSI:**
1. **Уровень приложений:** объединяет в себе сразу три верхних уровня модели OSI (прикладной, представления данных и сеансовый).
2. **Транспортный уровень:** полностью соответствует транспортному уровню OSI.
3. **Межсетевой уровень (Internet):** функционально соответствует сетевому уровню OSI.
4. **Уровень доступа к сети:** объединяет канальный и физический уровни модели OSI.

**Перечень стандартных стеков коммуникационных протоколов:**
* OSI
* TCP/IP
* IPX/SPX
* NetBIOS/SMB
* DECnet
* SNA

## 💻 3. Архитектура прикладного уровня

Прикладные протоколы Интернета определяют, как программы общаются между собой по сети.

**Базовые принципы построения сетевых приложений:**
* Архитектура **«Клиент‑сервер»** (где один узел запрашивает, а другой отвечает; пример: веб‑сервер и браузер, TELNET‑сервер и клиент).
* Архитектура **Peer‑to‑peer (P2P)** (все участники сети равноправны).

**Организация сетевого соединения (Сокеты):**
Конечная точка коммуникации в сети жестко задаётся с помощью **сокета** — программного интерфейса между прикладным и транспортным уровнями.
Сокет формируется из двух параметров:
1. **Имя хоста** (это может быть символьное имя или IP‑адрес).
2. **Номер порта** (определяет конкретный сервис: например, для HTTP это порт 80, для SMTP — порт 25). Стандартные порты строго регламентированы в документах RFC‑1700, RFC‑3232 и контролируются организацией www.iana.org.

**Классификация по формату передачи:**
* Текстовые протоколы (читаемые человеком).
* Бинарные протоколы (машинный код).

**Обязательные элементы стандарта прикладного протокола:**
Любой прикладной протокол должен строго регламентировать:
* Типы сообщений (виды запросов и ответов).
* Синтаксис сообщений (структуру).
* Семантику (смысловое назначение) полей.
* Правила генерации сообщений и реакции на них.

## 🔍 4. Глобальная система доменных имён (DNS)



Система имён необходима для перевода понятных человеку адресов в машинные IP-адреса.

**Эволюция доменных имён:**
* **Плоские имена:** исторически использовались для небольших локальных сетей (примеры: `NW1_1`, `MAIL2`).
* **Доменная система имён:** иерархическая структура для глобальных сетей (примеры: `en.wikipedia.org`, `msdn.microsoft.com`).

**Типы доменных имён:**
* Краткое доменное имя.
* Относительное доменное имя.
* Полное доменное имя (**FQDN** — Fully Qualified Domain Name).

**Классификация доменов верхнего уровня (TLD):**
* **Родовые (Generic TLD):** com, edu, org и т. д.
* **Национальные (Country Code TLD):** by, ru, uk, us и т. д.
* **Sponsored‑домены:** домены, зарегистрированные на конкретную компанию или организацию.

**Основы архитектуры DNS (Domain Name System):**
* Это централизованная служба, обладающая распределённой базой записей ресурсов.
* Пространство имён поделено на независимые зоны, обслуживаемые отдельными DNS-серверами.
* Разрешение имён (процесс поиска) выполняет специальный программный модуль — **резольвер DNS** (resolver).
* Формат записи ресурса: `DomainName Class Type Value`.
* *Основные типы записей:* тип **A** — указывает IP‑адрес хоста; **NS** — указывает на сервер имён верхнего уровня; **CNAME** — задает псевдоним; **MX** — указывает на почтовый сервер маршрутизации.
* **Обратная зона** (в доменах `in‑addr.arpa` / `ip6.arpa`) используется для обратного поиска: нахождения DNS‑имени по известному IP‑адресу.

**Схемы разрешения DNS‑имен:**
* Рекурсивная (косвенная схема поиска).
* Итеративная (нерекурсивная схема поиска).
* Гибридная схема.

**Пошаговый порядок разрешения имени в ОС Windows:**
Операционная система проходит строгий алгоритм поиска адреса:
1. Проверка совпадения с именем локального узла.
2. Поиск в локальном кэше DNS (включает предыдущие запросы и данные из файла `hosts`).
3. Отправка прямого запроса к внешнему DNS‑серверу.
4. Если запрашиваемое имя не плоское (а иерархическое) и не найдено — возвращается ошибка.
5. Иначе (для плоских имен) — продолжается поиск NetBIOS имени в кэше.
6. Запрос к WINS‑серверу.
7. Отправка широковещательного запроса в локальную подсеть (повторяется 3 раза).
8. Проверка локального файла `lmhosts`.
9. Возврат ошибки, если все шаги оказались безуспешными.

**Системное расположение файла `hosts`:**
* В ОС Windows: директория `/Windows/system32/drivers/etc/hosts`.
* В семействе GNU/Linux: директория `/etc/hosts`.

## 📡 5. Спецификация основных прикладных протоколов

### 📁 5.1. FTP (File Transfer Protocol)
* **Назначение:** стандартизированная передача файлов между удалёнными компьютерами.
* **Аутентификация:** поддерживается как строгая идентификация через учётную запись, так и публичный анонимный доступ.
* **Принцип работы:** уникален тем, что использует сразу два TCP‑соединения: управляющее соединение (по умолчанию порт 21) и отдельное соединение для непосредственной передачи потока данных.
* **Документация:** полное техническое описание стандарта приведено в RFC 959.

### 📜 5.2. TFTP (Trivial FTP)
* **Назначение:** тривиальная (максимально упрощённая) версия протокола FTP.
* **Особенности безопасности:** работает полностью без системы безопасности и идентификации.
* **Техническая реализация:** базируется на ненадежном протоколе транспортного уровня UDP (порт 69).
* **Передача:** данные фрагментируются и передаются фиксированными блоками ровно по 512 байт.
* **Сфера применения:** чаще всего используется системными администраторами для загрузки ОС в бездисковые рабочие станции по сети и для загрузки конфигурационных файлов в сетевое оборудование (маршрутизаторы/коммутаторы).

### ✉️ 5.3. Электронная почта (E‑mail)
Архитектура электронной почты строится на базе строгой **Модели X.400**, определяющей роли компонентов сети:
* **UA/MUA (User/Mail User Agent):** программный интерфейс конечного пользователя — почтовый клиент (например, Outlook или Thunderbird).
* **MTA (Message Transfer Agent):** ключевой узел маршрутизации — агент передачи сообщений, отвечающий за пересылку писем между серверами.
* **MDA (Message Delivery Agent):** локальный агент доставки сообщений, помещающий письмо в конкретный почтовый ящик пользователя.
* **MS (Message Store):** физическое хранилище, банк сообщений на сервере.

### 🌍 5.4. HTTP (HyperText Transfer Protocol)
*Примечание к конспекту: Протокол HTTP является фундаментальным протоколом прикладного уровня.*
Он обеспечивает передачу гипертекстовых документов (HTML) и медиа-ресурсов в глобальной сети WWW, базируясь на модели запрос-ответ. Работает преимущественно поверх надежного протокола TCP и является основой всего современного веб-программирования.
